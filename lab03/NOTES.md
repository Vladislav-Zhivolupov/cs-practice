git diff

Сравнивает два состояния проекта и показывает разницу (что именно изменилось: какие строки добавлены, удалены или изменены). 



git show

Фокусируется на одном объекте (коммите, теге, дереве файлов) и выводит о нём полную информацию: метаданные (автор, дата, сообщение) и детальный diff изменений. 



git log

Выводит список зафиксированных коммитов в репозитории, то есть показывает историю проекта.





git log -S"def" --oneline -- lab03/calc.py Не найдт ничего, т.к. ни в одной строке нет "def".



git blame lab03/calc.py Найдёт последние изменения строки в файле и покажет, кто и когда её изменил.





Как работает git restore

Без указания --source команда берёт версию файла из индекса и записывает её в рабочее дерево. То есть она отменяет локальные правки в файле, возвращая его к последнему проиндексированному состоянию (или к состоянию последнего коммита, если файл ещё не был добавлен в индекс).

После этой команды файk будет точно таким, каким он был в последнем индекс. Правки в этом файле безвозвратно теряются. 



Как работает git restore --source=

Опция --source позволяет взять версию файла из любого коммита, ветки или тега в истории репозитория. Затем эта версия записывается в рабочее дерево и индекс одновременно. Команда вернёт файл к состоянию, которое было два коммита назад. Содержимое из старого коммита перезапишет правки, и файл будет готов для добавления в индекс и коммита.



git reset --hard полностью сбрасывает состояние репозитория до указанного коммита, удаляя все изменения в рабочей директории и индексе.



git revert безопаснее для опубликованной истории, потому что он не переписывает её.
